ARCHITECTURE OVERVIEW
═══════════════════════════════════════════════════════════════════════════

Two-Level Parallelization Strategy:

Level 1: PARAMETER SETS (Outer - parfor)
├─ Parallelizes across 1...NUM_PARAM_SETS
├─ Each worker processes independent parameter set
├─ Status: ✓ Already highly optimized
└─ Performance: ~N*100% where N = num_workers

Level 2: CONTRACTS (Inner - optional nested parfor)
├─ Parallelizes within single batch
├─ When ENABLE_NESTED_PARFOR = true
├─ Status: ✓ New, optional feature
└─ Performance: +15-40% for large batches


BATCHING FLOW DIAGRAM
═══════════════════════════════════════════════════════════════════════════

parfor param_set = 1:NUM_PARAM_SETS
    [Generate trees - takes ~100ms]
    
    for batch = 1:num_batches
        [Monitor start_time]
        
        if ENABLE_NESTED_PARFOR
            parfor contract = 1:batch_size
                [Price call and put]
                [Apply noise]
                [Calculate IV]
            end
        else
            for contract = 1:batch_size
                [Price call and put]
                [Apply noise]
                [Calculate IV]
            end
        end
        
        [Track batch_time, valid_counts]
        [Show progress every 10%]
        [Combine and store results]
    end
end

KEY METRICS TO MONITOR
═══════════════════════════════════════════════════════════════════════════

1. Throughput (shown per batch):
   • 100-200 c/s: Slow, check for bottlenecks
   • 300-600 c/s: Good, normal operation
   • 600-1000 c/s: Excellent, well optimized
   • >1000 c/s: Outstanding, GPU or special optimization

2. Batch consistency:
   • All batches similar: Load balanced well
   • Some variation (±10%): Normal
   • High variance (>50%): Load imbalance, consider nested parfor

3. Memory usage:
   • Stable per batch: Good
   • Increasing over time: Check for leaks
   • >80% system memory: Reduce batch_size


TROUBLESHOOTING
═══════════════════════════════════════════════════════════════════════════

Problem: Throughput dropping
Cause: Memory pressure or cache thrashing
Solution:
  1. Reduce batch_size by 20-30%
  2. Check system memory with memory()
  3. Reduce NUM_PARAM_SETS if memory critical

Problem: Recommendation warning shown
Cause: Current batch_size differs from optimal
Solution:
  1. Try recommended batch_size
  2. Monitor new throughput
  3. Fine-tune within ±20% if needed

Problem: Nested parfor not helping
Cause: Tree computation is bottleneck (not contracts)
Solution:
  1. Disable nested_parfor
  2. Check if GPU acceleration helps
  3. Consider reducing tree size (m_h, m_x)

Problem: Inconsistent batch times
Cause: Worker heterogeneity or thermal throttling
Solution:
  1. Check CPU temperatures
  2. Monitor worker utilization
  3. Consider worker affinity settings
